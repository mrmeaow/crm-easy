# CRM-Easy

Offline-first desktop CRM for individuals — simple enough for anyone to operate.
Built with **Electron + React + TypeScript + SQLite**. Your data stays on your device.

> Full product requirements: see [SRD.md](./SRD.md)

## Status

MVP core in progress — all of these work end-to-end (renderer → IPC → SQLite):

- **Contacts** — CRUD, search, delete
- **Leads** — Kanban board with drag-and-drop between stages, add/edit/convert to contact
- **Pipeline stages** — customizable: add, rename, recolor, reorder, delete (guarded when in use)
- **Deals** — pipeline table, mark won/lost with reason, pipeline total + weighted forecast + won value
- **Tasks** — overdue/today/upcoming groups, due dates, desktop reminder notifications
- **Export** — contacts/leads/deals to `.xlsx` and `.csv` with column selection and localized headers
- **Backup & restore** — one-click local backup file, restore with safety copy; startup integrity check with auto-recovery from latest backup
- **i18n** — English / বাংলা runtime switching; settings persisted in DB (language, theme, currency)
- **Migrations** — schema versioned; applied automatically on startup

## Tech Stack

| Layer     | Choice                                                        |
| --------- | ------------------------------------------------------------- |
| Shell     | Electron 43 (contextIsolation, sandbox, no nodeIntegration)   |
| UI        | React 19 + TypeScript (strict) + Vite 7 (via electron-vite 5) |
| State     | Zustand + TanStack Query                                      |
| Local DB  | SQLite (better-sqlite3) + Drizzle ORM + versioned migrations  |
| i18n      | i18next + react-i18next (en / bn)                             |
| Packaging | electron-builder (deb, rpm, pacman, AppImage, NSIS, MSI)      |

## Project Structure

```
src/
├── main/          # Electron main process: window, SQLite/Drizzle, IPC handlers
│   ├── db/        #   schema.ts, init + migrations, seed
│   └── ipc/       #   contacts, settings (invoke handlers)
├── preload/       # Minimal contextBridge API (window.crm), typed
├── renderer/      # React UI
│   └── src/
│       ├── api/       # TanStack Query hooks
│       ├── i18n/      # i18next init + locales (en.json, bn.json)
│       ├── pages/     # Dashboard, Contacts, Settings, placeholders
│       ├── store/     # Zustand stores (settings: language/theme)
│       └── styles/    # CSS variables, light/dark themes
├── shared/        # Types + IPC channels + formatters (shared between main/renderer)
├── drizzle/       # SQL migration files (generated by drizzle-kit, committed)
└── tests/unit/    # Vitest unit tests
```

## Development

```bash
npm install            # installs deps + rebuilds better-sqlite3 for Electron
npm run dev            # electron-vite dev (HMR)
npm run typecheck      # TS strict, node + web projects
npm run lint           # ESLint
npm run format         # Prettier (write)
npm test               # Vitest unit tests
npm run build          # typecheck + electron-vite build → out/
npm run build:linux    # + electron-builder: .deb and .rpm (priority targets)
npm run build:linux:appimage   # + AppImage (portable fallback)
npm run build:linux:pacman     # + Arch .pacman (needs bsdtar, see note)
npm run build:win      # + NSIS .exe installer (build on Windows or in CI)
```

**Packaging priorities:** `.deb` (Debian/Ubuntu) and `.rpm` (Fedora/RHEL) are the
primary Linux artifacts, `.exe` (NSIS) for Windows. GitHub Actions builds all
targets on push/PR (artifacts) and attaches them to GitHub Releases on `v*` tags.

> Notes:
>
> - The `pacman` target requires `bsdtar` (`libarchive-tools` on Debian/Ubuntu;
>   the CI workflow installs it automatically).
> - Building the Windows NSIS installer on Linux requires `wine` (used to embed
>   the icon/metadata). On machines without wine, build on Windows or rely on CI:
>   `npx electron-builder --win nsis` works on the Windows runner.

### DB migrations (Drizzle)

```bash
npx drizzle-kit generate --name <name>   # after editing src/main/db/schema.ts
```

Migrations apply automatically on app startup. Never edit applied migrations —
create a new one.

### Notes

- **Data location:** `~/.config/crm-easy/data/crm-easy.db` (per-OS userData dir).
- **Security baseline:** contextIsolation + sandboxed renderer, narrow typed IPC bridge,
  CSP in production builds (dev CSP relaxed for HMR). No telemetry, no network calls.
- **react-router-dom is pinned at 7.18.2** — npm audit flags an RSC-mode CSRF advisory
  that is not applicable to this app (HashRouter, no SSR/RSC); the proposed
  "fix" would downgrade to a version with more severe advisories.
- **Linux sandbox:** on some dev machines Electron's SUID sandbox helper needs
  `chown root:root node_modules/electron/dist/chrome-sandbox && chmod 4755 ...`
  (or run with `--no-sandbox` for local testing only; packaged builds are unaffected).
- **Icons:** not yet added — add `build/icon.png` (512×512), `build/icon.ico`, etc.
  before the first release.
